# 历史搜题主页设计规格

日期：2026-08-05

状态：已实现并纳入当前分支基线

目标分支：`feat/history-search-home`

## 1. 背景与证据

本分支实施前，根路由中的“历史搜题”只负责高亮左侧导航和展开“试卷 → 题目”树；点击一级导航后，中央仍无条件渲染答疑欢迎页或当前会话。当前实现已在同一工作台中央补齐完整历史主页：第一层按试卷展示封面网格，第二层展示单份试卷中的题目列表，点击题目后打开原答疑会话。

本规格依据：

- `C:\AI4EDU\ui lowpoly\历史搜题\1.png`：试卷封面网格。
- `C:\AI4EDU\ui lowpoly\历史搜题\2.png`：单份试卷的题目列表。
- `C:\AI4EDU\ui lowpoly\历史搜题\notability参考.jpg`：封面卡片密度与“封面 + 元数据”的扫描方式。
- `PRODUCT.md`、`DESIGN.md` 与 `docs/superpowers/specs/2026-08-05-ui-visual-polish-design.md`：产品能力、明亮中庭视觉系统和不可破坏的工作台合同。
- 当前代码与真实页面：`apps/web/app/page.tsx`、`apps/web/components/workspace/SessionSidebar.tsx`、`apps/web/lib/api/types.ts` 及 `http://localhost:3000/`。

用户在可视化选择页明确选择 A「内容化纸张预览」，当前实现据此使用真实试卷名称和题目标题生成纸张式封面，没有为历史主页新增真实题图缩略图接口。

实施基线说明：本分支先原样验证并以独立提交收纳了前序任务提供的 `paper_id`、`paper_name`、试卷实体/API 与左侧试卷树，作为中央主页的继承前置；本规格没有重新设计或扩展该后端能力。中央历史主页只消费已有 `SessionHistoryItem[]` 并在前端派生试卷分组，不新增历史页请求，不逐份读取完整 session，也不形成 N+1 请求。

## 2. 设计决策与取舍

### 2.1 已选方案：同路由三态历史工作区

在现有根路由工作台内增加三种中央状态：

```text
历史试卷总览 → 单份试卷题目列表 → 原答疑会话
      ↑                 │
      └──── 返回 ───────┘
```

- 点击左侧一级导航“历史搜题”进入试卷总览。
- 点击试卷卡片进入该试卷的题目列表。
- 点击题目使用现有 `handleOpenSession` 打开原 session；不复制、不恢复成新分支。
- 题目列表左上角返回试卷总览。
- 左侧导航、顶部栏和右侧卡片系统仍属于同一根路由工作台，不新增 Next.js 页面路由。

中央历史视图不能只由 `activeNavigation === "history"` 推导。打开具体历史 session 时，现有逻辑同样把一级导航设为 `history`；若复用同一条件，点击题目后会继续停在历史列表。实现必须使用独立状态：

```ts
type HistoryView =
  | { mode: "overview" }
  | { mode: "paper"; paperId: string }
  | null;
```

`activeNavigation` 只描述一级导航归属，`historyView` 描述中央是否正在浏览历史页面。点击题目时先清空 `historyView`，再调用现有打开会话链路，以兼容“目标 session 已经打开”时的早退逻辑。

### 2.2 未选方案：真实题图优先

真实题图更接近 Notability，并能增强视觉记忆，但现有历史列表与试卷列表 API 均不返回缩略图。逐份调用完整 session 接口会形成 N+1 请求，同时下载消息、检查点和完整 data URL；新增轻量缩略图接口又会扩大后端、隐私与测试范围。用户已选择不采用该方案。

### 2.3 未选方案：只强化左侧树

仅优化左侧“试卷 → 题目”树能保持最小改动，但无法实现低保真图中的试卷封面总览、宽阔搜索空间和试卷详情页，也不能解决“点击历史搜题后中央内容不变化”的缺口，因此不采用。

## 3. 范围

### 3.1 本次包含

- 中央历史试卷总览。
- 中央单份试卷题目列表。
- 试卷名和题目名搜索。
- “最近更新”和“名称排序”两种排序。
- 内容化纸张封面。
- 加载、空历史、无搜索结果、选中试卷为空和并发删除状态。
- 从题目列表恢复原答疑会话。
- 题目级删除、运行中状态和禁用条件与左侧树保持一致。
- 桌面、平板、手机响应式与键盘访问。
- 修复当前打开会话仍可从左侧删除的现存不一致，并补回归测试。

### 3.2 本次不包含

- 不新增独立路由、URL 深链或浏览器历史层级。
- 不新增试卷创建、重命名、删除、收藏、归档、移动题目或分享。
- 不改变会话、试卷、教学动作、流式生成、卡片或 SQLite 数据模型。
- 不新增题图缩略图字段、接口、迁移或图片缓存。
- 不删除或替换左侧现有“试卷 → 题目”快速导航树。
- 不复制 Notability 的深色主题、蓝色按钮、iPad 顶栏或其品牌元素。
- 不改变右侧学习卡片的收纳、滑出/返回、翻面或字段映射合同。

## 4. 数据模型与派生规则

历史主页只消费现有 `SessionHistoryItem[]`，不新增后端请求。试卷总览数据由前端纯函数派生：

```ts
type HistoryPaperGroup = {
  id: string;
  name: string;
  items: SessionHistoryItem[];
  updatedAt: string;
  gradeBands: Array<"junior" | "senior">;
};
```

规则如下：

1. `paper_id` 存在时按该 ID 分组，名称使用 `paper_name`；旧会话统一进入 `id: "unclassified"`、名称“未分类题目”。
2. 每组题目保持 `updated_at` 从新到旧。
3. `updatedAt` 取组内最大的 session `updated_at`，不使用 `exam_papers.updated_at`；后者当前只记录试卷实体创建时间，并不会随答疑更新。
4. 总览只显示至少含一条历史 session 的组。清空会话后保留的空试卷实体不显示在“历史搜题”。
5. 封面取该组最近的 2–3 道题标题；公式继续交给 `MathText`，超长标题在封面内部按固定行数截断，不修改原始文本。
6. 学段标签只来自真实 `grade_band`：组内一致时显示“初中数学”或“高中数学”，混合时显示“混合学段”；未分类组优先显示“未分类”。
7. 试卷卡片底部显示真实试卷名、题目数和最近更新时间。

## 5. 页面与交互

### 5.1 进入与退出历史浏览

- 点击左侧“历史搜题”将 `activeNavigation` 设为 `history`、`historyView` 设为 `{ mode: "overview" }`，并关闭完整右栏。
- 进入历史浏览不会清空当前 session、输入草稿、消息时间线、pending card 或后台流。正在生成的会话继续由现有 controller 运行，历史列表仍显示“正在思考”。
- 点击“开始答疑”沿用现有清空当前视图逻辑，并把 `historyView` 设为 `null`。
- 点击知识库/错题库时把 `historyView` 设为 `null`，继续打开同一个右侧卡片库过滤视图。
- 从刷新恢复一个已有 session 时，一级导航仍显示“历史搜题”，但 `historyView` 为 `null`，中央显示该答疑会话。

### 5.2 试卷总览

中央历史主页头部包含：

- 标题“历史搜题”。
- 一句辅助说明“按试卷继续你的学习”。
- 搜索框“搜索试卷或题目”。
- 排序选择：“最近更新”（默认）和“名称排序”。

搜索同时匹配试卷名和组内题目标题。命中题目时保留其所属试卷卡片。搜索与排序完全在前端派生，不发额外请求。清除搜索后恢复当前排序下的完整列表。

“名称排序”使用 `localeCompare(..., "zh-CN")` 按试卷显示名升序排列；同名时以最近更新时间倒序作为稳定次序。总览搜索词和排序在当前页面生命周期内保留：进入试卷再返回、打开题目后再次点击“历史搜题”都能回到原浏览上下文；刷新页面后恢复默认的空搜索和“最近更新”。

试卷以卡片网格展示。整张卡片是进入试卷详情的单一操作，不在卡片上叠加删除、更多菜单或其他隐藏功能。

### 5.3 内容化纸张封面

封面是本页唯一的标志性视觉元素：

- 暖白纸张底、极浅网格和细边线，引用数学试卷/草稿纸语义。
- 使用真实学段、试卷名和最近 2–3 道题标题，不能填充虚构题目。
- 右上使用一个窄小的薰衣草、向日葵黄或绿色页签；颜色只帮助区分卡片，不编码业务状态。
- 纸张封面保持低对比，不与试卷名和日期争夺阅读优先级。
- 封面不使用网络图片、题图 data URL、装饰插画、熊猫角色或随机 emoji。
- 主题色来自上一视觉任务最终落地后的现有令牌；组件 JSX 不写独立原始十六进制色值。

### 5.4 单份试卷题目列表

点击试卷后，中央头部切换为：

- 左侧可访问返回按钮“返回全部试卷”。
- 当前试卷名与题目数量。
- 搜索框“搜索这份试卷中的题目”。

主体为纵向题目行。每行显示：

- 题目标题，使用 `MathText`。
- `message_count`、`checkpoint_count`（大于 0 时）、最近更新时间。
- 运行中的题目显示 Loader 与“正在思考”文字，不能只用颜色。
- 点击主体打开原 session。
- 右侧保留独立删除按钮；运行中、任一打开/删除请求进行中或该题就是当前打开 session 时禁用。

低保真图中的“一点对话记录缩略”解释为现有历史数据可可靠提供的会话摘要：消息数、检查点数、运行状态和更新时间。本次不批量下载完整消息正文，也不扩展 API 返回最后一条对话预览。

返回总览时保留总览搜索词与排序选择。若试卷内题目被另一个窗口或删除操作清空，详情页显示“这份试卷暂无历史题目”和返回按钮，不自动跳页。

### 5.5 删除与危险操作

- 题目级删除复用现有 `handleDeleteSession`，包括确认、请求恢复数据清理、草稿清理和当前视图处理。
- 当前打开 session 的删除按钮必须禁用；这一规则同时修正左侧 `SessionSidebar`。
- 运行中 session 不可删除。
- 删除最后一道题后，该试卷不再出现在总览，但空试卷实体继续保留，符合当前后端语义。
- “清空全部会话”只保留在左侧历史树底部，不在中央主页重复危险操作。
- 不出现试卷级删除按钮。

## 6. 状态与反馈

### 6.1 加载

首次历史加载时显示与最终卡片比例一致的 6 个轻量骨架；骨架不做持续闪烁，只使用轻微明度呼吸，并遵守 `prefers-reduced-motion`。

### 6.2 空历史

显示“还没有历史答疑”和现有动作“开始答疑”。点击后走现有新答疑逻辑，不新增另一套 composer。

### 6.3 无搜索结果

显示“没有匹配的试卷或题目”，并提供“清除搜索”按钮。该状态不把真实历史误报为空。

### 6.4 失败

`page.tsx` 增加独立 `historyLoadError: string`。`refreshHistory` 发起新请求时清空它，失败时写入它，成功时保持为空；现有 request id 继续阻止迟到请求覆盖新结果。中央历史页显示该错误和“重新加载”按钮，重试调用同一个 `refreshHistory`，不创建并行请求链。历史加载错误不得只留在底部输入器中，也不得覆盖答疑流、卡片或模型配置产生的现有 `runtime.error`。

## 7. 视觉系统

历史主页延续上一任务最终确认的“专注光场 · 明亮中庭”和 C4 色彩方向：高彩绿色、向日葵黄、明亮低饱和薰衣草紫。实现时使用 C4 合同中的 `--stage-canvas`、`--stage-line`、`--stage-forest`、`--stage-sage`、`--stage-sage-soft`、`--stage-yellow`、`--stage-yellow-soft`、`--stage-lavender-deep` 与现有中性色，不得把选择页中的示例色值复制成第二套令牌。

纸张底使用 `--stage-canvas`，网格与边界从 `--stage-line` 派生；学段标签使用浅绿色面和深绿文字；右上页签只在 `--stage-yellow`、`--stage-lavender-deep`、`--stage-sage` 三者中按稳定试卷 ID 映射。黄色只作装饰，不能复用 `--warning` 语义令牌。

### 7.1 空间

- 顶部栏和左侧学习空间保持现有位置、尺寸和材质。
- 历史主面是连续暖白阅读画布，不做独立深色页面或由大量重阴影卡片拼成的后台仪表盘。
- 完整右侧卡片栏在浏览历史主页时关闭，中央自然扩展；左侧快速树继续存在。
- 历史内容使用比消息列略宽的内容容器，以容纳 3 列试卷卡片，但不改变 `.conversationPanel` 祖先的 transform/filter，避免破坏学习卡片测量合同。

### 7.2 层级与尺寸

- 页面标题约 28–32px；试卷名约 15–17px；题目行标题 14–16px；元数据 11–12px。
- 卡片使用 12–16px 圆角、1px 细边和现有普通卡片柔影；hover/focus 最多上移 2px。
- 工具控件使用清楚文本标签，不把低保真图的灰色块机械实现为无标签图标。
- 主要触控目标至少 44×44px；焦点使用现有全局 `:focus-visible` 合同。

### 7.3 响应式

- 视口宽度 `> 1100px`：3 列试卷卡片。
- 视口宽度 `761–1100px`：2 列；左栏沿用完整抽屉，不变成窄图标条。
- 视口宽度 `≤ 760px`：1 列；搜索占满一行，排序位于同一工具区的下一行或右侧；题目行转为纵向卡片，标题优先，元数据自然换行，删除按钮保留独立 44px 区域。
- 不产生页面级横向滚动；公式只在自身容器内横向滚动。
- 手机进入题目详情时，返回按钮始终位于内容头部；左侧抽屉行为继续遵守现有合同。

### 7.4 动效

- 总览卡片 hover/focus、页面状态切换使用 150–220ms 标准缓动。
- 从总览到详情只做一次轻微淡入/位移，不使用卡片放大全屏或复杂共享元素动画。
- 所有新增动效在 `prefers-reduced-motion: reduce` 下关闭位移和呼吸。

## 9. 测试与验收

### 9.1 自动测试

1. 纯函数测试：试卷分组、未分类、组内排序、最大更新时间、试卷/题目双字段搜索、名称排序。
2. 组件测试：总览、详情、加载、空历史、无结果、空试卷、运行中、删除禁用和返回按钮。
3. 页面合同测试：点击历史入口进入总览；点击题目前清空历史中央视图并复用 `handleOpenSession`；打开同一 session 的早退仍显示会话。
4. 现有前端全量测试、lint、typecheck 和 build 全部通过。
5. 现有学习卡片视觉合同与冻结文件哈希不因本任务改变。

### 9.2 浏览器验收

在 1440×900、1280×800、1024×768、768×1024、390×844 和 375×812 验证：

- 点击“历史搜题”中央切换到试卷总览，顶部栏和左侧树保持。
- 搜索能按试卷名和题目名过滤；排序结果稳定。
- 内容化纸张封面只显示真实数据，长标题和公式不破版。
- 点击试卷进入题目列表；返回保留总览搜索与排序。
- 点击题目打开原会话，消息、checkpoint、卡片、草稿和运行状态正常恢复。
- 浏览历史期间，其他正在生成的 session 不被停止。
