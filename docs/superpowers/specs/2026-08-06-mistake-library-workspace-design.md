# 错题合集、试卷归档与可拖动卡片窗口设计

日期：2026-08-06

状态：已确认，待实施

目标分支：`codex/mistake-library-workspace`

## 1. 目标

在保留现有“历史搜题”快速树的前提下，重新组织错题相关导航，并统一试卷、会话和学习卡片的生命周期：

1. “历史搜题”继续保留搜索框和“试卷 → 会话”快速树，不删除已有快速入口。
2. 左侧“错题库”改为父级，下设“错题合集”和“错题库”。
3. 现有历史试卷总览和单份试卷题目列表迁入“错题合集”；不再保留另一份名为“历史搜题”的中央页面。
4. 删除某份试卷的最后一个会话时，同时删除该试卷实体，使其从历史分组和新建图片答疑的选卷列表中消失。
5. 已归档知识卡和题目卡不随会话或试卷删除；尚未保存的临时卡片继续随会话删除。
6. 新卡片默认进入其来源会话所属试卷的同名卡片目录，保存时仍可为当前卡片手动改选其他目录。
7. 同名试卷删除后重新创建时，继续复用原来的同名卡片目录和其中历史卡片。
8. 当前悬浮知识卡和题目卡改为可拖动窗口，保留现有生成、打开和返回卡片架的自然衔接动画；消息正文不再为悬浮卡片缩窄或绕排。

## 2. 已确认的产品语义

### 2.1 两类“文件夹”是独立实体

系统必须明确区分：

- **试卷实体**：数据库中的 `exam_papers`，用于组织 sessions，并出现在题图答疑的试卷选择器中。
- **卡片目录**：数据库中的 `card_folders`，用于长期组织已归档的知识卡和题目卡。

删除空试卷只删除 `exam_papers`，绝不按名称级联删除 `card_folders`。卡片目录的生命周期独立且更长，因此能够承接同名试卷删除前后的所有卡片。

### 2.2 会话删除边界

- 删除单个会话时，删除该 session 及其消息、检查点、运行记录、稳定事件和诊断日志。
- 删除前若该 session 正在生成，继续返回冲突，不把浏览器断流视为已停止。
- session 删除后若其原 `paper_id` 已无其他 session 引用，则在同一 SQLite 写事务内删除该 `exam_papers` 记录。
- 未分类会话没有 `paper_id`，删除时不创建或删除任何试卷。
- “清空全部会话”在同一事务内删除全部 sessions 和全部 `exam_papers`。
- 已保存卡片保留，`live_session_id` 按现有外键规则置空；未保存卡片按现有触发器删除。

该规则明确覆盖以下旧设计：

- `2026-08-05-history-search-home-design.md` 中“删除最后一道题后保留空试卷”的描述。
- `2026-08-06-composer-and-exam-paper-cleanup-design.md` 中“单条会话删除不自动删除空试卷”的描述。

这两份旧规格的其他无冲突部分继续有效。

### 2.3 卡片默认位置与手动选择

- 有所属试卷的卡片：默认位置为“按试卷归档 / `<试卷名>`”。
- 无所属试卷的卡片：继续使用“默认知识卡片”或“默认题目卡片”。
- 知识卡和题目卡共用同一个试卷目录；知识库和错题库只过滤展示各自的卡片类型。
- 保存弹窗继续显示目录选择器。用户改选其他目录时，只覆盖当前卡片的位置，不改变该试卷后续卡片的默认位置。
- 卡片保存后仍允许使用现有移动、复制功能调整目录。

## 3. 数据模型

### 3.1 受管试卷卡片目录

在当前 Alembic head `0012_merge_exam_run_heads` 之后新增迁移。迁移为 `card_folders` 增加可空的受管目录元数据：

```text
managed_kind: NULL | "paper_archive_root" | "paper_archive"
managed_key:  NULL | 稳定业务键
```

数据库使用 CHECK 约束保证 `managed_kind` 和 `managed_key` 同时为空或同时非空，并限制 `managed_kind` 只能取上述两个受管值。`managed_key` 不通过公共写接口开放。非空 key 使用 `COLLATE NOCASE` 条件唯一索引。系统创建一个受保护的根目录：

```text
按试卷归档
  ├─ 期中测试
  ├─ 一元二次方程练习
  └─ ……
```

根目录使用固定 `managed_key="paper-archive-root:v1"`。新建时可以生成新的 folder ID；升级时若已经存在根级同名目录，则复用其原 ID，保留其中现有卡片和子目录，再将其标记为受管、不可重命名、移动或删除。所有运行时代码只按 `managed_key` 找根，不依赖固定 ID，也不覆盖或删除用户数据。

每份试卷对应一个 `managed_kind="paper_archive"` 子目录。它的 `managed_key` 为 `paper-archive:v1:` 加试卷清理后名称，其中仅把 ASCII `A-Z` 映射为 `a-z`。该算法与现有 `exam_papers(name COLLATE NOCASE)` 的身份语义一致：名称前后空白不参与身份；不折叠名称内部空白，也不使用会把更多 Unicode 字符合并的 NFKC/casefold 规则。

如果受管根下已经存在与试卷同名的普通子目录，ensure 过程复用该目录、保留其内容并将其升级为受管子目录，不创建带后缀的第二份目录。升级后的目录进入保护状态；卡片仍可移出。这样既避免名称冲突，也让用户已有的同名归档自然加入统一规则。

受管子目录不可重命名、移动或删除，但其中卡片仍可移入、移出、复制和删除。这保证“同名试卷”始终指向稳定的归档位置，又不限制用户整理卡片。

目录保护同时检查原有 `is_system` 和新的 `managed_kind`。公共接口禁止在受管根下新建或移入普通目录，也禁止重命名仍位于该根下的历史普通子目录；这些历史子目录可以移出或删除。运行时 ensure 若遇到升级前遗留的同名普通子目录，仍按上述认领规则原位升级。repository 还要验证 `paper_archive` 的直接父级确实是唯一 `paper_archive_root`。

删除试卷后，空的受管试卷目录有意长期保留，以承接未来同名试卷和旧卡片；本次不提供自动清理或手工删除受管目录的入口。

### 3.2 试卷到卡片目录的连接

为 `exam_papers` 增加：

```text
card_folder_id TEXT NOT NULL
  REFERENCES card_folders(id) ON DELETE RESTRICT
```

`exam_papers.card_folder_id` 同时建立唯一索引，保证同一时刻至多一份活动试卷绑定某个受管试卷目录。SQLite 迁移通过建新表/拷贝数据的方式完成非空字段和外键约束，不依赖仅添加可空列后的应用层约定。

升级现有数据时：

1. 为每个现存试卷 ensure 一个同名受管子目录。
2. 保留所有原 paper ID，重建并回填 `exam_papers.card_folder_id`，再重建原 `uq_exam_papers_name` 和新的 folder 唯一索引。
3. 对仍能通过 `live_session_id → sessions.paper_id` 找到试卷、且当前仍位于对应卡片类型系统默认目录的卡片，回填到该试卷目录。
4. 已经位于用户自建目录的卡片视为用户明确选择，不移动。
5. `live_session_id IS NULL`、无所属试卷或来源已不可恢复的历史卡片保持原位置。

第 3 步明确采用启发式：旧 schema 无法分辨“系统自动落在默认目录”和“用户明确选择默认目录”，因此仍位于类型默认目录的可关联卡片统一视为可安全回填；这是一次性升级行为。未来保存的显式选择由最终 `folder_id` 直接保留，不再依赖该推断。

对第 3 步发生目录回填的卡片，迁移同步按 `card_id` 更新其稳定 `card.ready` 事件 payload 中的 `folder_id`，保持断线重放与 `study_cards` 权威行一致；事件序号、类型、时间和其他 payload 字段不变。找不到匹配事件的已保存旧卡允许只更新业务行；仍未保存的 pending 卡若缺少匹配事件则迁移失败并整体回滚，不能留下恢复前后默认目录不一致的状态。

迁移完成前执行 `PRAGMA foreign_key_check` 并要求结果为空；任一认领、回填、事件转换或外键检查失败都整体回滚。downgrade 重建旧版 `exam_papers` 结构、移除受管元数据和相关索引，但保留“按试卷归档”及其子目录和卡片为普通用户目录，不移动或删除卡片；downgrade 后同样执行外键检查。

### 3.3 同名重建

`create_exam_paper(name)` 在现有 `BEGIN IMMEDIATE` 写事务内：

1. 清理并验证名称。
2. 按现有 NOCASE 规则复用同名活动试卷；若不存在则继续。
3. 按 `managed_key` ensure 同名受管卡片目录。
4. 创建新的 `exam_papers` 记录并写入该目录 ID。

因此删除后的同名试卷会获得新的 `paper_id`，但复用原 `card_folder_id`。并发创建同名试卷时，只能得到一份活动试卷和一个受管卡片目录。

显式创建但尚未产生任何 session 的空试卷继续保留并出现在选卷列表中，因为它是用户刚创建、准备使用的实体。自动 prune 只发生在“删除一条曾属于该试卷的最后 session”以及“清空全部会话”这两个删除事务中；`GET /api/exam-papers` 不按 `session_count=0` 全局过滤，否则会让新建试卷在首道题提交前消失。

## 4. 删除事务与并发

### 4.1 单会话删除

单删 repository 使用项目现有 `@with_sqlite_busy_retry` 和 `BEGIN IMMEDIATE`，在一个事务内完成：

```sql
SELECT paper_id FROM sessions WHERE id = ?;
-- 再次检查该 session 是否存在 queued/running run；有则回滚并返回 409
DELETE FROM sessions WHERE id = ?;
DELETE FROM exam_papers
WHERE id = :paper_id
  AND NOT EXISTS (
    SELECT 1 FROM sessions WHERE paper_id = :paper_id
  );
COMMIT;
```

`paper_id` 为空时跳过第二次删除。删除必须使用删除前读取的准确 ID，不能按试卷名称清理。

路由层保留 coordinator 的快速预检；SQLite 中的 run 状态检查是最终权威，用于堵住“路由预检完成后新 run 入队”的窗口。删除服务使用专用 domain conflict 异常并稳定映射为 HTTP 409，不复用语义不匹配的普通异常。

所有创建 session 的路径都必须在自己的写事务内重新验证 `paper_id`，包括普通 `SessionRepository.create`、批量 `SessionStartAcceptanceMixin.start_sessions` 和复制恢复 `SessionHistoryRepositoryMixin.restore`。这避免最后一条 session 删除与新建/恢复 session 交错时把刚被引用的试卷删掉。若客户端提交了刚被另一窗口删除的试卷 ID，返回清晰的“所选试卷已不存在，请重新选择”，前端刷新试卷列表；不能只依赖路由层的事务外预检或让原始 FK 异常变成 500。

### 4.2 清空全部

`DELETE /api/sessions` 在一个 `BEGIN IMMEDIATE` 事务内检查全局活动 run，然后依次删除 sessions 和 `exam_papers`。受管卡片目录、已归档卡片、模型配置继续保留。

### 4.3 日志顺序

SQLite 是 session 恢复的唯一权威。删除接口必须先提交 SQLite，再尽力删除 JSONL/Markdown 诊断日志。日志删除失败只记录 warning，不把已经成功的业务删除改报为失败，也不留下“数据库仍有 session、诊断日志却先丢失”的状态。

### 4.4 前端一致性

单删接口保持现有 204 合同，不要求前端猜测服务端是否 prune 了 paper。成功后前端先递增历史和试卷请求代次，再权威刷新 `historyItems` 与 `examPapers`；本地即时移除只作为视觉反馈，不能代替刷新结果。全删成功后递增同样的请求代次并直接清空两份状态。这样删除前发出的迟到响应不能恢复旧会话或旧选卷项。

多窗口不增加实时同步通道。若另一窗口删除数据：

- 打开已删除 session 时沿用 404 恢复并移除本地历史项。
- 使用已删除 paper 创建 session 时显示上述明确错误并刷新试卷列表。

## 5. 卡片生成与保存数据流

### 5.1 生成时即确定默认目录

不能只修改保存接口的空值 fallback。当前前端会以 `StudyCard.folder_id` 初始化目录选择器，并在保存时显式回传该 ID。因此 `record_tutor_action()` 生成 pending 卡片时必须：

1. 从 session 读取 `paper_id`。
2. 从活动试卷取 `card_folder_id`。
3. 有试卷时把该 ID 同时写入 `study_cards.folder_id` 和 `card.ready` 稳定事件。
4. 无试卷时继续按 `card_type` 使用现有两类系统默认目录。

### 5.2 保存时的后端兜底

题目卡的 `save_card()` 和知识卡的 `accept_card_dismissed_continue()` 都遵循同一优先级：

1. 客户端明确提交的 `folder_id`。
2. 卡片生成时已经写入的 `study_cards.folder_id`。
3. 对应卡片类型的系统默认目录。

卡片保存、知识卡继续命令、幂等输入和稳定事件继续在现有原子事务边界内完成。该改动不能削弱 `session_inputs` 幂等接纳、checkpoint 原子写入或 `session_runs` 串行约束。

### 5.3 目录列表刷新

创建试卷可能同时创建新的受管卡片目录。`ExamPaperPublic` 和前端 `ExamPaper` 显式增加只读 `card_folder_id`；`CardFolderPublic` 只公开 `managed_kind`，不公开可被误用的 `managed_key`。前端在 `createExamPaper` 成功后并行调用现有试卷刷新与卡片/目录刷新链路，确保 `examPapers` 和 `card_folders` 都来自成功写入后的新快照，也避免卡片选择器持有“有 folder_id 但 options 中无该目录”的状态。

卡片/目录刷新与历史、试卷刷新一样维护请求代次。创建试卷、删除会话或目录变更后递增对应代次，旧请求的迟到响应不能覆盖新目录树。

## 6. 导航和中央页面

### 6.1 历史搜题快速树

保留现有“历史搜题”分组中的全部能力：

- 展开/收起。
- 搜索试卷或题目。
- 按试卷展开会话。
- 打开原答疑会话。
- 删除单个会话。
- 清空全部会话。
- 当前会话、运行中、打开中和删除中的禁用状态。

“历史搜题”不再拥有一套独立中央总览。点击其主标签时展开快速树，并把中央内容导航到唯一的“错题合集”页面，作为保留旧操作习惯的快捷入口；页面标题、ARIA 和空状态均使用“错题合集”语义。点击树内会话仍直接打开原答疑会话。

### 6.2 错题库导航层级

左侧导航变为：

```text
开始答疑
历史搜题
  └─ 原快速树（保留）
知识库
错题库
  ├─ 错题合集
  └─ 错题库
```

- 点击“错题库”父级默认进入“错题合集”，并展开两个子项。
- “错题合集”渲染原 `HistoryWorkspace` 的试卷封面总览和单份试卷题目列表。
- “错题库”打开现有右侧 `StudyCardSidebar` 的 `problem_card` 过滤视图，不替换中央会话或合集内容。
- “知识库”继续打开 `knowledge_card` 过滤视图。
- 内部变量可继续沿用 `history*` 命名以控制改动范围，但用户可见文案不得再把中央合集称为“历史搜题主页”。

打开合集时，唯一高亮目的项是“错题合集”；“历史搜题”的展开状态独立维护，不同时显示两个选中导航项。通过快速树打开 session 时，高亮“历史搜题”，并在树内继续标记活动 session。父级和同名子级的无障碍名称分别使用“错题库分组”和“打开错题库”，避免读屏时无法区分。

打开合集中的题目后进入原会话，中央合集状态清空、高亮切换为“历史搜题”，快速树继续用 session ID 标记当前会话；刷新恢复已有历史 session 时采用相同归属。新建答疑才高亮“开始答疑”。再次点击“错题合集”返回先前保留的总览搜索和排序上下文；卷内搜索属于详情的临时状态，离开详情后重置。

右侧单类型卡片库打开时，知识库或错题库子项获得高亮；关闭右栏后恢复底层中央内容对应的导航高亮。会话头打开的“全部卡片”只是工具面板，不改变主要导航归属。

侧栏整体保持可滚动，历史快速树内部使用 `min-height: 0` 和独立滚动区。即使窗口高度较低、快速树展开，知识库、错题库父级和两个子项仍必须可通过滚动与键盘到达。

### 6.3 错题合集与错题库的数据边界

- 错题合集展示全部历史答疑 sessions，按试卷分组；当前没有“是否答错”字段，不额外推断对错。
- 错题库展示已归档 `problem_card`。
- 删除合集中的 session 不删除错题库卡片。
- 两类视图使用同一受管试卷目录名称，但分别展示各自的数据类型和数量，不把 session 当作卡片，也不把 card folder 当作 `exam_papers`。

知识库和错题库都渲染完整的共享目录树；目录计数与卡片列表按当前 `card_type` 过滤。同一试卷目录可以在知识库显示知识卡数量、在错题库显示题目卡数量，另一类型不会混入列表。

错题库过滤模式下，全局操作必须避免误解：导出入口明确标为“导出全部学习卡片”；知识库/错题库单类型视图隐藏全局清空，只有“全部卡片”视图保留“清空全部学习卡片”。

## 7. 可拖动卡片窗口

### 7.1 范围

以下两类卡片共用同一窗口外壳：

- 当前会话最新的 pending 知识卡或题目卡。
- 从中央右缘竖向卡片架或右侧知识库/错题库打开查看的已归档知识卡或题目卡。

历史消息中已经锚定的旧卡片仍保留其内联折叠与“回到当前题”行为，不把整条消息历史改造成多个互相遮挡的自由窗口。用户正在操作的那一张卡片始终是唯一浮动窗口。

### 7.2 拖动模型

新增独立 `DraggableCardWindow` 外壳和纯几何工具：

- `>900px` 时在卡片标题区提供独立、至少 44×44px 的可聚焦拖动把手；标题、按钮、表单控件、正文选择和滚动区域不会启动拖动。把手通过方向键每次移动 16px、`Shift+方向键` 每次移动 4px，`Home` 恢复默认位置，并提供对应无障碍说明。
- 使用 Pointer Events，同时支持鼠标、触控笔和触屏；拖动开始后调用 pointer capture，结束或取消时释放。
- `touch-action: none` 只设置在专用拖动把手上，不阻断卡片内容或消息区的正常滚动。
- 高频坐标存入 ref，并通过 `requestAnimationFrame` 批量写入 transform，避免每个 pointermove 触发整页 React 渲染。
- 以 `.messageViewport` 的当前可视矩形作为拖动边界，并保留 12px 内边距；该边界天然排除会话标题和 composer 的主要提交控件。窗口至少保留完整标题栏可见。
- 窗口最大高度不超过可用区域；标题栏和主要动作保持可见，超长卡片内容在窗口内部滚动，不能依靠把窗口拖出屏幕才能访问底部内容。
- 同时观察窗口和边界矩形；浏览器缩放、侧栏开合、composer 高度变化、卡片翻面、进入编辑、验证错误展开或窗口 resize 后都重新夹取当前位置。
- 切换 session 或换成另一张 pending 卡时恢复默认位置；同一张已归档卡在一次打开期间保留拖动位置，关闭后不写入 localStorage。
- 键盘仍可访问窗口内全部操作；拖动不是完成保存、关闭或阅读的唯一方式。

`≤900px` 采用现有全宽安全位置并隐藏拖动把手，不启用自由拖动，避免与页面滚动、右侧抽屉和软键盘手势冲突；所有卡片操作仍保持可用。`prefers-reduced-motion` 关闭入场位移和 FLIP 动画，但在 `>900px` 不禁用直接拖动。

从右侧卡片库打开归档卡时，先记录触发项和矩形。`≥1320px` 的桌面持久右栏保持打开，关闭时可返回仍可见的来源项；`≤1319px` 的抽屉先关闭再显示卡片窗口，关闭卡片时使用轻量退场而不飞向已经隐藏的抽屉，且不自动重开抽屉，而把焦点恢复到会话头“打开卡片库”按钮。两条路径都必须保证窗口位于可见层级，不能被抽屉遮罩覆盖。

### 7.3 动效衔接

保留三条现有动效语义：

1. 新生成卡片从右侧自然进入默认窗口位置。
2. 从卡片架打开时，从触发卡片矩形 FLIP 到浮动窗口。
3. 关闭已归档卡片时，从当前位置 FLIP 返回原卡片架项目并恢复焦点。

外层 motion layer 负责入场/返回动画，内层 drag layer 负责用户位移，避免两个行为同时写同一个 `transform`。动效期间暂时禁用拖动；动效完成后才进入可交互状态。若来源卡片已不存在，直接关闭并恢复到可用的上级焦点，不播放错误的回程动画。

关闭一张已拖动的归档卡时，先记录当前 drag offset 和窗口矩形；在同一个 `flushSync` 交接中让外层关闭动画首帧继承该可见位置、把内层 drag offset 归零，再以来源卡片矩形计算终点。窗口不能先跳回默认位置再飞回卡片架。

Escape 对两类状态采用不同语义：已归档卡走正常关闭/返回状态机；pending 卡只取消当前拖动并把焦点交还拖动把手，不能绕过保存、舍弃或知识卡继续命令而卸载。

### 7.4 移除文字避让

删除 `MessageTimeline` 的 `floatingObstacleRef`、`floatingObstacleActive`、`floatingCardAvoidanceWidth()`、ResizeObserver/MutationObserver 避让链路，以及 `.avoidsKnowledgeCard` 和 `--knowledge-card-avoidance-width` 样式。

消息始终使用原本完整宽度。浮动卡片允许覆盖消息区域，用户通过拖动改变位置；滚动消息、公式横向滚动和消息重试按钮不再触发布局反复测量或宽度抖动。

## 8. 错误处理与恢复

- 受管目录 ensure、试卷创建或删除事务失败时整体回滚，不产生只有 paper 没有 folder 或相反的半状态。
- 受管目录名称或唯一键冲突返回稳定的业务错误，不把原始 SQLite 异常暴露给前端。
- 受管目录在 API 层继续作为普通 `CardFolderPublic` 返回，并暴露足够的只读元数据让前端禁用重命名、移动和删除入口。
- 保存卡片时目标目录已被另一窗口删除，返回 404/409，保留 pending 卡片与用户编辑内容，刷新目录列表后允许重试。
- 删除 session 成功而日志删除失败时，接口仍返回成功；日志记录 warning。
- 删除最后会话后，错题合集详情若正在显示该试卷，则切回合集总览并显示短暂、非阻塞反馈；快速树和选卷列表同步移除该试卷。
- 拖动过程中失去 pointer、组件卸载、切换卡片或触发上述 Escape 行为时必须清理 capture、animation frame 和全局监听器。
