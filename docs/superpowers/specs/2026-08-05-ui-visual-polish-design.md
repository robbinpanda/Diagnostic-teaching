# 答疑工作台 UI 视觉重构设计规格

日期：2026-08-05

状态：已批准（2026-08-05；部分信息架构与卡片边界已被后续规格替代）

实施分支：`feat/ui-visual-polish`

> **后续规格说明（2026-08-06）：** [`2026-08-06-mistake-library-workspace-design.md`](./2026-08-06-mistake-library-workspace-design.md) 继续沿用本文“明亮中庭”视觉、历史快速树、卡片主题和 FLIP 动效，但更新错题导航、试卷删除语义、受管目录及可拖动卡片窗口。下文相应旧约束仅记录本次视觉重构当时的边界。

## 1. 已批准方向

本次重构采用「专注光场」中的 A「明亮中庭」作为主构图，并吸收 C「层叠地平线」更明显但克制的绿紫渐变与空间层次。

- 已批准高保真构图：[focus-light-a-luminous-atrium.png](../../../.impeccable/mocks/focus-light-a-luminous-atrium.png)
- 用户补充指示：以 A 为主，增加一点 C 的渐变；左侧历史搜题必须继续保持“试卷 → 题目”的树形格式；卡片外观可以优化，但右侧收纳与自然滑动形式不变。
- 构图图中的示例题目、会话文字和占位卡片只表达布局与气质，不代表新增业务内容或功能。
- 现有产品名称与信息文案保持不变；不新增熊猫、卡通角色、吉祥物或无关主题插画。

## 2. 问题与目标

现有界面功能完整，但整体以连续白色平面和常规三栏为主，顶部、侧栏、答疑区与输入区缺少统一的空间秩序；在中等宽度下，侧栏又容易挤压中央数学内容，历史树甚至会缩成只能看到图标的状态。

本次目标是：

1. ~~在不改变业务功能、根路由状态模型和信息层级的前提下~~，把界面整理成一个完整、成熟的学习工作台。该“不改变”约束仅适用于本视觉任务，后续规格已更新导航与状态边界。
2. 用暖白主面、低饱和鼠尾草绿、浅薰衣草色晨光、半透明侧翼和轻微纹理建立视觉辨识度。
3. 让中央答疑成为最明亮、最连续的阅读平面，左右工具区自然后退但保持清楚可发现。
4. 改善栅格、间距、对齐、文字层级、焦点状态和多尺寸响应式表现。
5. 恢复代码中已经接线、但当前侧栏未渲染的“清空全部会话”入口，避免以视觉简化换取功能缺失。

## 3. 不在本次范围内

- ~~不改 API、数据模型或卡片持久化。~~ 该视觉任务当时未修改这些能力；后续规格已新增受管卡片目录和试卷目录外键。教学 action、流式解析与会话恢复不变量仍保持。
- 不新增页面路由；开始答疑、历史搜题、知识库和错题库仍在根路由工作台内切换状态。后续只在同一根路由内增加“错题合集”子导航，没有新增路由。
- 不新增产品模块、营销区、统计面板、排行榜、插画人物或装饰性内容。
- 不改变卡片内容字段、正反面内容对应关系、保存/舍弃/编辑/移动/导出流程；卡片主题色、材质、排版和正反面视觉允许统一优化。
- 不引入新的 UI 组件库、字体包或动画依赖。

## 4. 不可破坏的信息层级与功能

### 4.1 顶部

顶部继续只承载产品标识、AI 工具入口和账户区域。现有熊猫标记不扩展为新的装饰系统，也不在其他区域复制。

### 4.2 左侧学习空间

~~一级顺序保持为以下四个平级入口：~~ 这是当时结构；现行“错题库”为父级，下设“错题合集”和“错题库”，历史搜题快速树继续保留：

1. 开始答疑
2. 历史搜题
3. 知识库
4. 错题库
5. 本地安全存储提示

“历史搜题”展开后继续保持以下精确层级：

```text
历史搜题
└── 搜索试卷或题目
    ├── 试卷 A（题目数量）
    │   ├── 题目 1（消息数、更新时间、运行状态、删除）
    │   └── 题目 2（消息数、更新时间、运行状态、删除）
    └── 未分类题目
        └── 题目 …
```

- 搜索同时匹配试卷名和题目名。
- 有搜索词时，匹配的试卷组自动展开；当前会话所在试卷也自动展开。
- 试卷节点保持展开/收起、题目节点保持恢复原会话和单条删除；选择题目后左栏保持展开，只在用户主动收起或首次进入窄屏时关闭。
- 打开会话期间，对应题目的删除操作禁用；刷新恢复已有会话后，一级导航同步显示“历史搜题”。
- 忙碌、空列表和无搜索结果三种状态继续保留。
- “清空全部会话”放在历史树底部的次级危险操作区，继续使用现有确认文案和处理逻辑，不挤占试卷/题目树的主阅读区域；正在清空、存在任一生成中会话或历史为空时禁用。
- 不新增手工试卷级删除、重命名或移动题目能力；~~清空会话只删除会话及日志，空试卷记录继续保留。~~ 现行清空会话会删除全部试卷，单删最后 session 也同步删除对应试卷；已归档卡片与受管卡片目录保留。

### 4.3 中央答疑

顺序保持：会话标题与状态 → 卡片收纳标签 → 消息时间线/检查点/对话内卡片 → 输入器。消息、题图、数学公式、教学动作标签、检查点、错误、生成/停止和语音状态均不删减。

### 4.4 右侧卡片库

右侧继续承载知识卡、题目卡、文件夹、剪贴板、编辑、移动、删除、导出与清空卡片功能。知识库和错题库仍通过相同右栏按类型过滤，不拆成新页面。

## 6. 视觉与构图

### 6.1 总体空间

- 桌面端应用不再贴满纯白视口，而是以一个有轻微内缩、圆角和细边框的完整工作台壳层悬浮在晨光背景上。
- 背景以鼠尾草绿为左侧基底、暖白为中央亮区、极浅薰衣草色为右上/右侧补光；渐变主要存在于壳层外和上方三分之一，不穿透到正文造成低对比。
- 中央答疑平面最亮、对比最高；左侧与右侧使用近白半透明表面和轻微背景模糊，形成“侧翼后退、中央前移”的层次。
- 使用一个小尺寸、低不透明度、无语义的细颗粒栅格图作为环境纹理；该资产单独生成，不从构图截图裁切。纹理只覆盖背景，不覆盖数学正文和卡片。
- `.appShell`、`.conversationPanel` 和卡片 dock 的祖先不使用 `transform`、`scale` 或 `filter`；卡片滑出依赖源/目标 `getBoundingClientRect()`，光场只能通过背景、尺寸、边框和局部侧栏 `backdrop-filter` 实现。

### 6.2 色彩令牌

视觉令牌：

- 主墨色 `#26372B`
- 深鼠尾草 `#55705C`
- 中鼠尾草 `#78977D`
- 浅鼠尾草 `#D5E2D3`
- 暖白画布 `#FCFDF9`
- 雾白侧翼 `rgba(250, 252, 248, 0.76)`
- 浅薰衣草 `#E8E4F2`
- 细线 `rgba(60, 78, 64, 0.12)`

危险、警告、成功、信息状态继续沿用现有语义色，不用主渐变替代状态含义。

### 6.3 字体与层级

- 不加载网络字体；使用 Windows 和中文系统字体栈：`Segoe UI`、`PingFang SC`、`Microsoft YaHei` 及系统 sans-serif 回退。
- 产品名 18–20px；会话标题 15–16px；正文 14–16px；次要元数据 11–12px。
- 主要依靠字号、字重、留白和明度建立层级，不使用大面积全大写、夸张字距或渐变文字。
- 数学公式、长回答和题目标题保留现有 KaTeX/`MathText` 呈现，不改内容宽度计算逻辑。

### 6.4 栅格与表面

- 宽屏三栏参考宽度：左侧 252–264px，中央 `minmax(0, 1fr)`，右侧 304–320px。
- 顶部栏约 62–66px；会话头约 58px；主要间距以 4px 基线组织，常用间距 8/12/16/24/32px。
- 外壳圆角 22–24px；主要内部面圆角 16–18px；按钮和输入控件圆角 10–14px。避免所有元素都变成独立漂浮卡片。
- 阴影只用于应用外壳、抽屉和输入器；列表和普通内容优先用细线与背景明度区分。

### 6.5 中央阅读与输入

- 消息列保持当前宽度与 DOM/测量结构，中央增加稳定的暖白阅读面和更明确的上下留白。
- 学生消息、AI 回复、检查点和对话内交互不改变角色顺序；只统一头像、气泡边界、动作标签与段落节奏。
- 欢迎页保留现有标题、说明和三种输入方式；将过于常规的轨道/纸片装饰弱化为与晨光方向一致的抽象层次，不增加插画或角色。
- 输入器保持底部工作台结构，使用清楚的主次工具分组、半透明暖白表面和足够的键盘焦点对比；发送/停止状态与禁用逻辑不变。

### 6.6 卡片视觉

- 卡片继续通过稳定的 `card.id` 获得主题变化；知识卡使用低饱和鼠尾草、灰绿和淡薰衣草变体，题目卡保留暖金/燕麦色区分，但整体降低饱和度并与工作台晨光统一。
- 正面更像清晰的学习索引：标题、关键关系/题目摘要和核心原理形成三层字级；背面更像结构化复盘页：推导/步骤、使用场景、易错点和最终答案分区明确。
- 可以增加极轻纸感颗粒、半透明内容块、细线和更精确的阴影；不加入贴纸、熊猫、卡通图标或与学科无关的装饰。
- 翻面按钮位置、`aria-pressed`、正反面内容字段和现有切换逻辑不变；视觉重做不得把背面内容压缩到不可滚动或不可读。

## 7. 响应式行为

### 宽屏（`>= 1320px`）

- 左栏、中央和按需打开的右栏同处壳层栅格。
- 右栏关闭时中央自然扩展；右侧收纳卡片标签仍按原位置和动画出现。
- 沿用当前行为：应用初始不强制打开完整右栏，以确保当前会话的收纳卡片标签仍是首要入口；用户主动打开知识库/错题库后才显示完整右栏。

### 中等宽度（`761–1319px`）

- 中央答疑优先占满可用宽度，左、右侧栏改为保留完整内容的抽屉，而不是把左栏压成看不到“试卷 → 题目”树的 72px 图标条。
- 初次进入时侧栏关闭；从会话头或导航按钮打开后显示完整树/卡片库，并使用遮罩关闭。
- 使用媒体查询监听器同步断点变化，窗口从宽屏缩到中屏/手机时不会保留错误的侧栏开放状态。
- 抽屉不得改变右侧收纳卡片滑入中央卡片的几何测量链路。

### 手机（`<= 760px`）

- 应用壳层全屏，顶部栏降至约 60px，左右侧栏继续作为互斥抽屉。
- 使用 `100dvh` 并保留 `100vh` 回退，避免软键盘和移动浏览器工具栏遮挡。
- 消息、输入器和弹层不产生横向滚动；工具栏可以在自身区域横向滚动。
- 触控目标尽量达到 44×44px；卡片在手机端的已有布局和翻面控制不改。

## 8. 状态、动效与无障碍

- 所有主要按钮保留可访问名称；键盘焦点使用 2px 深鼠尾草轮廓和外偏移，不能只靠颜色。
- 正文对比度至少 4.5:1；状态文字同时使用图标/文案，不只使用色点。
- 新增的壳层、抽屉和 hover 动效控制在 150–240ms；卡片自身动画完全沿用现有数值。
- `prefers-reduced-motion: reduce` 继续生效；新环境渐变不做持续漂移动画。
- 背景纹理和伪元素必须 `pointer-events: none`，不进入可访问树。
- 空状态、加载、错误、禁用、确认和流式生成状态均需要在桌面与手机布局中可见且不跳版。
