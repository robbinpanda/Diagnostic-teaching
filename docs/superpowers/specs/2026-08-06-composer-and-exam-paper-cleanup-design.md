# 输入区与试卷清理修复设计

## 目标

修复首页输入区的两个可见问题，并让“清空全部会话”同步清除已经失去业务意义的试卷记录：

1. 从首页输入区移除“初中 / 高中”年级段选择器。
2. 保证推理强度为“关闭”时，触发器完整显示“推理 · 关闭”。
3. 清空全部会话后，新上传题图选择试卷时不再显示此前会话所属的旧试卷。

## 范围

### 年级段选择器

本次只移除首页输入区中的 `GradeBandPicker` 及其 `TutorComposer` 属性连接。页面仍保留 `gradeBand` 状态，未从其他入口指定时继续使用现有默认值 `junior`；会话 API、SQLite 字段和教学提示中的年级段语义均保持不变，以便后续在其他页面重新提供选择入口。

### 推理强度触发器

保留现有控件结构、菜单与交互，仅调整触发器布局约束：控件应为“推理 · 关闭”及下拉箭头预留稳定空间，标签不能依赖省略号隐藏当前档位。桌面工具栏允许正常换行；窄屏继续使用现有横向滚动策略。

### 清空会话与试卷

`DELETE /api/sessions` 的成功语义扩展为：

- 删除全部 sessions 及其数据库级联业务数据；
- 保留已归档的全局学习卡片和模型配置；
- 删除全部 `exam_papers`；
- 删除全部 session 诊断日志。

SQLite 操作在同一数据库事务内先删除 sessions、再删除 exam papers。前端收到成功响应后立即清空 `historyItems` 与 `examPapers`，并递增试卷列表请求代次，使删除前发出的旧请求不能把旧列表写回状态。单条会话删除行为不变，不自动删除空试卷。

## 错误与并发行为

- 存在活动生成流时，清空请求继续返回 `409`，不删除会话或试卷。
- 数据库清理失败时事务整体回滚，前端保留当前列表并显示错误。
- 数据库删除成功后，浏览器草稿与日志清理由现有路径继续处理；浏览器草稿清理仍是尽力而为。
- 删除操作成功后，即使旧的试卷列表请求稍后完成，也不得恢复旧试卷选项。

## 验收与测试

- `TutorComposer` 不再渲染年级段选择器，也不再接收其值和回调。
- 新建文字或图片答疑仍提交有效的默认 `grade_band=junior`。
- 推理强度为 `none` 时，触发器完整显示“推理 · 关闭”，且箭头不覆盖文字。
- 创建试卷和其会话后执行 `DELETE /api/sessions`，历史会话与试卷列表都为空。
- 清空会话后，归档卡片与模型配置仍存在。
- 前端清空成功路径同时清空试卷状态并使在途试卷请求失效。
- 运行后端测试、前端组件测试、TypeScript 类型检查；涉及页面构建时补跑生产构建。

## 非目标

- 不新增年级段的新入口。
- 不删除或迁移 `grade_band` API/数据库字段。
- 不改变单条会话删除后的空试卷保留策略。
- 不重做输入区视觉风格或推理强度菜单。
